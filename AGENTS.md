# Strength learning library

A static-first Next.js/TypeScript library teaches original, source-grounded strength and hypertrophy courses in English and Simplified Chinese. `site/` is publishable application source; the browser needs no backend, keys, authentication, or runtime AI.

## Content and learner state

- Each book becomes one incrementally registered course. Course pairs are `site/content/courses/{id}.en.json` and `{id}.zh-CN.json`; models live in `site/lib/types.ts`. Localized Markdown companions live in `site/content/lessons/{id}/{locale}/` and are generated by `scripts/validate-content.ts --write-markdown`.
- Both locales share stable course, chapter, lesson, section, question, option, glossary, and interaction IDs. Keep all learner-facing fields localized. Preserve source-language citations and the same numerical values, assumptions, and correct answer IDs. No silent English fallback for missing Chinese content.
- Read every substantive source section, maintain a private source coverage ledger, and author original educational explanations. Preserve qualifications and distinguish source claims from generated examples. Copyright ownership is not implied by possession; never publish source chapters or illustrations without established rights.
- Explicit `[term](term:term-id)` links identify contextual terms. Search indexes contain rendered public educational text only. Keep note text exactly as entered.
- Persistence uses language-independent references and the asynchronous `LearningRepository` interface in `site/lib/learning-store.ts`. Evolve schemas with migrations; validate imports. Version 1 adds optional-import `bookmarks` (migrated to an empty array) and optional position `sectionOffset` for locale-aware section restoration, plus an optional `preferences.locale` (`en`/`zh`); older v0/v1 imports without it remain valid and retain an existing language choice when merged. The legacy separate locale key is read once as a fallback. Theme changes retain locale, and locale changes retain theme. Learning data remains on the browser/device without automatic synchronization.

## Private/public boundary

`books/` (and future `book/`), `private/`, extraction/OCR, temporary renders, credentials, caches, and personal learner data are private authoring inputs. They must never enter GitHub, Sites source packages, static output, or browser bundles. Review actual staged files and package contents; `.gitignore` is insufficient. Publish only intentional course prose, original diagrams, code, project skills, and concise nonconfidential documentation.

## Quality and publishing

Run from repository root:

```sh
node --import ./site/node_modules/tsx/dist/loader.mjs scripts/validate-content.ts --write-markdown
cd site
npm run typecheck
npm run build
```

Then perform browser checks for both locales, desktop/mobile navigation, language switching and anchors, search, glossary keyboard behavior, quiz scoring/retry, interactions, notes, reload persistence, and import/export. Structural checks cannot establish full coverage or semantic parity: inspect the private ledger and both course versions. Record actual results and limitations.

Synchronize only reviewed publishable source to the intended GitHub repository; keep Sites-managed and GitHub remotes separate and preserve history. Follow the installed Sites skill for source packaging, static deployment, and audience verification. Do not claim public deployment from a private preview.

## Project skills

Read the relevant `.agents/skills/<name>/SKILL.md` explicitly if the environment has not discovered project skills. Open this repository as the workspace and start a new chat to refresh discovery when needed.

- `book-to-course`: full-source processing, source ledger, original bilingual course authoring and registration.
- `learning-site-design`: responsive bilingual documentation layout, themes, typography and accessibility.
- `learning-interactions`: source-grounded models, scientific verification, localized accessible controls.
- `course-quality-review`: coverage, fidelity, semantic translation parity, questions, interactions and publication safety.

Use Chinese for progress and handoff unless the user requests another language.
