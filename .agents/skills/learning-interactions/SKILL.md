# Learning interactions

Read the target course, private coverage ledger, `site/lib/types.ts`, and existing interaction implementation. Choose a source-grounded concept that answers a concrete learning question; avoid decorative sliders and unsupported physiological predictions.

Record stable interaction/lesson IDs, source locator, objective, rationale, input/output units, assumptions, constraints, verification, and a noninteractive alternative. Use lightweight React/SVG and language-independent computation/state. Localize every label, instruction, caption, and feedback message. Match IDs and numerical assumptions across translations.

Supported types are volume (sets × repetitions × load), intensity (load ÷ stated 1RM × 100), recovery (qualitative source-backed scenarios), and sequence (ordered technique/programming explanation). Volume-load is bookkeeping, not a direct hypertrophy or fatigue prediction. Do not prescribe individual training from a generic model. New types need typed implementation and validation before authors use them.

Verify dimensional consistency, known examples, bounds, zero/negative/nonfinite values, rounding, and source qualifications. Distinguish exact relationships from simplified teaching assumptions. Provide keyboard/touch controls, reset, readable output without color dependence, reduced motion, and a text/table alternative. Preserve values during locale changes.

Check diagram geometry and scientific meaning against the source; generated anatomy is not authority. Test both locales and calculation boundaries. Update the private source ledger and run content validation and meaningful calculation checks.
